# Shlink Go 重写技术选型

> 状态：已确定  
> 日期：2026-10-21  
> 目标：使用 Go 重写 Shlink 后端，继续兼容官方 `shlink-web-client` 的 REST API v3 契约。  
> 约束：只依赖 PostgreSQL；不使用 Redis、RabbitMQ、Mercure、Matomo；个人使用，单实例部署。

## 1. 最终选型

| 层次 | 选型 | 说明 |
|---|---|---|
| 语言 | Go 1.27 | 当前开发环境版本，单二进制部署 |
| HTTP 框架 | Gin | 负责外层路由、中间件和公开短链跳转 |
| REST API 层 | Huma v2 + `humagin` | 负责 `/rest/v3` 的 typed handler、参数解析和 OpenAPI |
| 数据库 | PostgreSQL 16+ | 开发环境为 PostgreSQL 18，只支持 PostgreSQL |
| 数据访问 | Bun | query builder/ORM，底层走 `database/sql` |
| 日志 | `log/slog` | 标准库结构化 JSON 日志 |
| 配置 | `caarlos0/env` | 环境变量配置，不引入 Viper |
| CLI | Cobra | `serve`、`migrate`、`api-key:*` |
| 数据库迁移 | `bun/migrate` | 与 Bun 保持一致；迁移文件放 `migrations/` |
| GeoIP | `geoip2-golang` + GeoLite2-City | 数据库文件由部署环境提供 |
| User-Agent | `mileusna/useragent` | 解析浏览器、设备、Bot 标记；需用 Shlink 行为做验收 |
| 测试 | `testcontainers-go` + `kin-openapi` | 真实 PostgreSQL 集成测试 + 契约校验 |
| 部署 | Docker + Caddy/Nginx | 单进程，TLS 和反向代理在外层 |

## 2. 选型理由

### 2.1 Gin

- 生态成熟，团队使用成本低。
- `humagin` 提供官方 Gin adapter，Huma 可以直接注册到 `*gin.Engine`。
- Gin 负责非 REST 的公开路由：短链跳转、`robots.txt`、`favicon.ico`、404/orphan 处理。
- 性能足够。这个项目的重定向请求会访问 PostgreSQL，框架层的差异不是瓶颈。

注意：

- 使用 `gin.New()`，不要用自带 Logger/Recovery 的 `gin.Default()`。
- 设置 `RedirectTrailingSlash = false`，否则 `/abc/` 会被 Gin 自动重定向，破坏 `SHORT_URL_TRAILING_SLASH`。
- 显式设置 `SetTrustedProxies(...)`，避免伪造 `X-Forwarded-For`。
- `GET /:shortCode/track` 由 Gin 独立处理，返回 tracking pixel，避免被 extra path 逻辑当成普通短链路径。

### 2.2 Huma

Huma 的价值：

- handler 输入/输出是 Go 类型，减少手写参数解析。
- 自动生成 OpenAPI 3.1，方便内部文档和调试。
- 支持 `OmittableNullable[T]` 模式，适合 Shlink PATCH 中“未传 / 传 null / 传值”的三态语义。
- 支持 per-operation middleware，适合挂 API Key 认证。

但 Huma 不能直接按默认行为使用：

- Huma 自动校验失败默认返回 `422 Unprocessable Entity`，错误体是 `errors[]`。
- Shlink 要求 `400 Bad Request`，类型为 `https://shlink.io/api/error/invalid-data`，并可能包含 `invalidElements`、`shortCode`、`tag` 等额外字段。
- Huma 生成的 OpenAPI 是“Go 实现的文档”，不是 Shlink 的 API 契约；兼容性仍以仓库中的 `docs/reference/swagger` 为准。

因此约定：

- Huma 只负责 `/rest/v3`。
- 每个 operation 设置 `SkipValidateParams: true`、`SkipValidateBody: true`，业务校验在 handler/service 中手写。
- 使用自定义 Problem Details 错误类型，不依赖 Huma 默认 `ErrorModel`。
- Huma 的 `/openapi.json`、`/docs`、`/schemas` 默认关闭，或只挂到内部路径。

### 2.3 Bun

选择 Bun 的主要原因是开发效率：

- CRUD、动态筛选、排序、分页写起来比手写 SQL 快。
- SQL-first，比 GORM 更可控。
- 支持 PostgreSQL、事务、批量插入、迁移。
- 与 Gin/Huma 没有耦合，handler 直接调用 Bun service。

需要接受的代价：

- Bun 基于 `database/sql`，不是 pgx 原生接口；个人使用场景性能足够，但无法直接使用 pgx 的 `CopyFrom`。
- 类型安全弱于 sqlc/Ent，NULL、零值、字段更新需要格外小心。
- 复杂统计和权限过滤仍然建议使用 `NewRaw` 手写 SQL。

### 2.4 log/slog

- 标准库，少一个日志框架依赖。
- 支持 JSON handler、结构化字段和日志级别。
- 适合 Gin 自定义中间件统一输出访问日志和错误日志。
- 不使用 `gin.Logger()`，避免两套日志格式。

### 2.5 其他辅助选型

- **配置**：环境变量 + `caarlos0/env`，保持 12-factor；不使用 Viper。
- **CLI**：Cobra，一个二进制包含 `serve`、`migrate` 和 `api-key:*` 命令。
- **迁移**：`bun/migrate`，迁移文件嵌入二进制；启动时可自动执行，同时提供 `migrate` 命令。
- **GeoIP**：`geoip2-golang` 读取 GeoLite2-City；数据库缺失时返回空位置，不阻塞启动。
- **User-Agent**：先用 `mileusna/useragent`；如果 Bot/设备识别与 Shlink 差异明显，再换 `uap-go` 或补充规则集。解析逻辑封装在 `internal/ua`。
- **测试**：PostgreSQL 集成测试使用 `testcontainers-go`，不使用 SQLite 代替 PostgreSQL。

## 3. 总体架构

采用**模块化单体、单进程**：

```text
                         ┌─────────────────────┐
Browser / Web Client ───▶│      Gin Engine     │
                         │                     │
                         │ 外层 middleware:     │
                         │ request-id, slog,    │
                         │ recover, CORS,       │
                         │ body limit           │
                         └──────────┬──────────┘
                                    │
                 ┌──────────────────┼──────────────────┐
                 ▼                  ▼                  ▼
          /rest/v3/*          /:shortCode           / 与 NoRoute
          Huma API            短链跳转              orphan / 404
                 │                  │                  │
                 └──────────────────┼──────────────────┘
                                    ▼
                          feature services
             shorturl / visit / tag / domain / redirect /
                    redirectrule / apikey
                                    │
                                    ▼
                         Bun + database/sql
                                    │
                                    ▼
                              PostgreSQL
```

架构原则：

- 不拆微服务，不引入消息队列。
- 所有持久化只走 PostgreSQL。
- 业务逻辑按功能包拆分，不按 `controller/service/repository` 机械分层。
- HTTP DTO、数据库 model、领域对象三者分离；Bun model 不直接序列化成 API 响应。
- 访问记录先同步写入；如果后续实测重定向延迟受影响，再考虑进程内有界队列，不提前引入。

## 5. 关键设计

### 5.1 Gin 与 Huma 的职责边界

Gin 负责：

- 外层中间件：request ID、slog、recovery、CORS、body limit。
- 公开路由：`GET /:shortCode`、`GET /:shortCode/*extra`、`GET /robots.txt`、`GET /favicon.ico`。
- `NoRoute`：404/orphan 分类、域名级跳转、错误页面。
- `GET /:shortCode/track` 返回 1×1 GIF 并记录有效访问；`/rest/*` 不进入短链 fallback。

Huma 负责：

- `/rest/v3/*` 的全部 REST 接口。
- 输入解码、typed handler、OpenAPI schema。
- per-operation 认证中间件。
- 输出 DTO 序列化。

Gin 初始化示意：

```go
r := gin.New()
r.RedirectTrailingSlash = false
r.SetTrustedProxies([]string{"127.0.0.1", "::1"})

cfg := huma.DefaultConfig("Shlink Go API", "5.1.7")
cfg.OpenAPIPath = ""
cfg.DocsPath = ""
cfg.SchemasPath = ""
api := humagin.New(r, cfg)
```

### 5.2 API 契约

- 契约来源：根目录 `README.md` + `docs/reference/swagger`（上游 v5.1.7）。
- 实现完整 `/rest/v3`，包括 `shorten`；`/{shortCode}/track` 作为非 REST 路由实现；不实现 v1/v2；提供 `migrate-shlink` 从 Shlink 5.x PostgreSQL 导入。
- Huma 生成的 OpenAPI 只用于内部文档，不作为兼容性验收依据。
- 所有响应 DTO 手写，字段名、可空性、日期格式必须与上游一致。
- `domain`、`title`、`validSince`、`validUntil` 等可以为 `null` 的字段使用指针或自定义 nullable 类型，不能使用 `omitempty` 把 `null` 变成“字段缺失”。
- PATCH 使用 `OmittableNullable[T]` 区分“未传”“传 null”“传值”。
- 日期统一使用 RFC3339/ISO-8601，必要时自定义时间类型，避免 `time.Time` 默认格式与上游不一致。
- `GET /rest/v3/health` 和 `/rest/health` 返回版本 `5.1.7`，用于 Web 客户端的功能开关；不要返回 Go 应用自己的版本号。

### 5.3 错误模型

定义 Shlink 风格的 Problem Details：

```go
type Problem struct {
    Type            string   `json:"type"`
    Title           string   `json:"title"`
    Detail          string   `json:"detail"`
    Status          int      `json:"status"`
    InvalidElements []string `json:"invalidElements,omitempty"`
    ShortCode       string   `json:"shortCode,omitempty"`
    Tag             string   `json:"tag,omitempty"`
    Domain          string   `json:"domain,omitempty"`
}

func (p *Problem) Error() string   { return p.Detail }
func (p *Problem) GetStatus() int { return p.Status }
```

约定：

- `Content-Type: application/problem+json`。
- 错误 `type` 使用 `https://shlink.io/api/error/<type>`。
- 至少覆盖：`invalid-data`、`non-unique-slug`、`short-url-not-found`、`invalid-short-url-deletion`、`domain-not-found`、`forbidden-tag-operation`、`tag-conflict`、`tag-not-found`、`mercure-not-configured`、`missing-authentication`、`invalid-api-key`、`not-found`。
- `invalid-data` 带 `invalidElements`；短链不存在带 `shortCode`；标签不存在带 `tag`。
- Huma 的框架级错误通过自定义 `huma.NewError` 转成同一种 Problem；业务错误由 handler 直接返回 `*Problem`。
- 因为 Huma 自动校验固定返回 422，REST operation 默认关闭自动校验，改为手写校验，确保 Shlink 的 400 行为。

### 5.4 认证与 API Key 权限

- Web 客户端通过 `X-Api-Key` 请求头认证。
- API Key 只保存 `SHA-256` 哈希，原文只在生成时输出一次。
- 无角色的 Key 是管理员 Key。
- 角色：
  - `AUTHORED_SHORT_URLS`
  - `DOMAIN_SPECIFIC`
  - `NO_ORPHAN_VISITS`
- 多个角色同时存在时，短链级限制按交集生效；`NO_ORPHAN_VISITS` 作为额外限制叠加。
- `DOMAIN_SPECIFIC` 的 `meta` 保存 `domain_id` 和 `authority`，不能指向默认域名。
- 权限过滤集中到一个 `Scope` 结构，所有短链、标签、域名、访问统计查询都显式传入：

```go
type Scope struct {
    IsAdmin        bool
    AuthorAPIKeyID *int64
    DomainID       *int64
    DenyOrphan     bool
}
```

- 默认域名使用 `domains` 表中的一行表示，API 返回短链时把默认域名映射成 `domain: null`。
- `apiKeyName` 过滤：管理员可过滤任意 Key；受限 Key 只允许过滤自身，其他值忽略。
- 带短链级限制的 Key 重命名/删除标签返回 `403 forbidden-tag-operation`。
- 初始 Key：`INITIAL_API_KEY` 只在 `api_keys` 为空时生效。
- 管理入口只保留 CLI：
  - `api-key:generate`
  - `api-key:list`
  - `api-key:disable`
  - `api-key:delete`
  - `api-key:rename`

### 5.5 短链跳转与访问记录

跳转流程：

1. 从 `Host` 解析域名并规范化；找不到时回退默认域名。
2. 按 `(domain_id, short_code)` 唯一索引查询短链。
3. 校验 `validSince`、`validUntil`、`maxVisits`。
4. 只有 `hasRedirectRules = true` 时才加载并执行重定向规则。
5. 规则引擎按 priority 升序匹配，所有条件 AND；未命中使用 `defaultLongUrl`。
6. 拼接目标 URL：
   - `SHORT_URL_TRAILING_SLASH`
   - `EXTRA_PATH_MODE` 的 `default` / `append` / `ignore`
   - `forwardQuery`
   - `DISABLE_TRACK_PARAM`
7. 同步记录 visit 并更新短链计数器；失败只写日志，不阻塞 302。
8. 返回 `302 Found`。

访问记录：

- 记录 referer、User-Agent、IP、visitedUrl、redirectUrl、potentialBot、时间。
- GeoIP 使用原始 IP 查询；按配置匿名化后再落库。
- UA 只解析一次，Bot 判断和设备/浏览器条件共用解析结果。
- visit 插入与 `short_urls` 的 `visits_total`、`visits_non_bots`、`visits_bots` 更新放在同一事务。
- 删除短链访问时同步重置计数器。
- 当前不引入异步队列；如果以后需要，使用进程内有界 channel + 批量写入 + 优雅关闭时 flush。

Orphan / 404：

- `/` 记为 `base_url`。
- 第一段看起来像短链但查不到、已过期或达到最大访问次数，记为 `invalid_short_url`。
- 其他未匹配路径记为 `regular_404`。
- 根据域名配置执行 `baseUrlRedirect`、`regular404Redirect`、`invalidShortUrlRedirect`。
- `/rest/*`、`/robots.txt`、`/favicon.ico`、`/:shortCode/track` 不进入 orphan 逻辑。

### 5.6 数据模型与索引

建议表：

- `domains`
  - `id`、`authority`、`is_default`、三个域名级 redirect 字段。
  - 默认域名使用 partial unique index 保证唯一。
- `short_urls`
  - `id`、`domain_id`、`short_code`、`long_url`、`title`、`date_created`。
  - `valid_since`、`valid_until`、`max_visits`、`crawlable`、`forward_query`。
  - `author_api_key_id`、`has_redirect_rules`。
  - 计数列：`visits_total`、`visits_non_bots`、`visits_bots`。
  - 唯一索引 `(domain_id, short_code)`。
- `tags`
  - `id`、`name` 唯一。
- `short_url_tags`
  - 主键 `(short_url_id, tag_id)`。
- `visits`
  - `id`、`short_url_id`（orphan 时为空）、`visited_at`、`referer`、`user_agent`、`remote_ip`。
  - `visited_url`、`redirect_url`、`potential_bot`、`orphan_type`。
  - 位置字段直接放 visits 表：`country_code`、`country_name`、`region_name`、`city_name`、`latitude`、`longitude`、`timezone`，避免每次列表 JOIN。
- `redirect_rules`
  - `short_url_id`、`priority`、`long_url`、`conditions jsonb`。
  - 唯一索引 `(short_url_id, priority)`。
- `api_keys`
  - `id`、`name` 唯一、`key_hash` 唯一、`expires_at`、`enabled`。
- `api_key_roles`
  - `api_key_id`、`role`、`meta jsonb`，唯一索引 `(api_key_id, role)`。

关键索引：

- `short_urls (domain_id, short_code)` 唯一。
- `short_urls (date_created)`、`short_urls (visits_total)`、`short_urls (visits_non_bots)`。
- `visits (short_url_id, visited_at DESC)`。
- `visits (visited_at DESC)`。
- `visits (visited_at DESC) WHERE orphan_type IS NOT NULL`。
- `short_url_tags (tag_id, short_url_id)`。
- `short_urls` 的 `short_code`、`long_url` 使用 `pg_trgm` GIN 索引支持 `searchTerm` 的 `ILIKE`。

### 5.7 Bun 使用约束

- 使用 `pgx/v5/stdlib` 注册 `pgx` driver，然后：

```go
db := bun.NewDB(sqlDB, pgdialect.New())
```

- 设置连接池参数：`SetMaxOpenConns`、`SetMaxIdleConns`、`SetConnMaxLifetime`。
- 固定 CRUD 用 Bun query builder；`GET /short-urls` 的多条件筛选、排序、分页，以及访问统计聚合，使用 `NewRaw` 或清晰的 query builder。
- PATCH 禁止直接 `UpdateModel` 全字段更新；显式指定要更新的列。
- 短链列表的 tags 批量查询后在内存组装，不要逐条加载。
- 唯一约束、外键错误使用 `pgconn.PgError` 的 SQLSTATE 映射到 Problem Details（例如 `23505` -> `non-unique-slug`）。
- Bun model 不直接作为 API DTO；所有响应经过 DTO 映射。
- 迁移使用 `bun/migrate`，不要同时引入 goose/golang-migrate。启动时执行迁移需加 `pg_advisory_lock`，避免多实例并发。

### 5.8 日志

- 使用 `slog.NewJSONHandler`，输出到 stdout。
- Gin 外层中间件记录：`request_id`、`method`、`path`、`status`、`duration_ms`、`api_key_name`。
- 不记录完整 API Key，不记录请求体，不记录敏感 query。
- Huma 错误由外层中间件统一记录一次，避免 handler 和框架重复打印。
- Gin recovery 自定义为 slog + Problem Details 500，不使用默认 `gin.Recovery`。

### 5.9 配置

建议环境变量：

| 变量 | 说明 |
|---|---|
| `DATABASE_URL` | PostgreSQL DSN |
| `LISTEN_ADDR` | HTTP 监听地址，默认 `:8080` |
| `DEFAULT_DOMAIN` | 默认短域名 |
| `IS_HTTPS_ENABLED` | 生成短链时是否使用 `https` |
| `INITIAL_API_KEY` | 空库时创建管理员 Key |
| `GEOLITE2_CITY_DB_PATH` | GeoLite2-City.mmdb 路径 |
| `TRUSTED_PROXIES` | 可信代理 CIDR 列表 |
| `CORS_ALLOWED_ORIGINS` | 允许的 Web 客户端来源 |
| `SHORT_URL_TRAILING_SLASH` | 短链 trailing slash 行为 |
| `EXTRA_PATH_MODE` | `default` / `append` / `ignore` |
| `DISABLE_TRACK_PARAM` | 不转发的 query 参数 |
| `DEFAULT_SHORT_CODES_LENGTH` | 自动 short code 长度 |
| `DEFAULT_SHORT_CODES_CHARS` | 自动 short code 字符集 |
| `ANONYMIZE_REMOTE_IP` | 是否匿名化访问 IP |
| `LOG_LEVEL` | `debug` / `info` / `warn` / `error` |

配置在启动时校验，缺失关键项直接失败；不使用 Viper。

### 5.10 部署

- 单二进制，模板和静态资源通过 `embed` 打入。
- Docker 多阶段构建，运行镜像只包含二进制和必要 CA 证书。
- Caddy/Nginx 终止 TLS，设置 `TRUSTED_PROXIES`。
- PostgreSQL 独立容器或外部服务；GeoLite2 文件挂载到容器。
- 启动流程：加载配置 -> 打开数据库 -> 执行迁移 -> 初始化 `INITIAL_API_KEY` -> 启动 HTTP server。
- 优雅关闭：`signal.NotifyContext`，等待 HTTP 请求和数据库事务结束。
- 健康检查：`/rest/health` 和 `/rest/v3/health`，检查数据库连接。
- 不引入 Redis、RabbitMQ、Mercure、Matomo。

## 6. 测试策略

### 单元测试

- 重定向规则 11 类条件及 priority/AND 语义。
- URL 拼装：query 转发、trailing slash、extra path 三种模式、`DISABLE_TRACK_PARAM`。
- API Key `Scope` 交集、`apiKeyName` 过滤、标签操作限制。
- short code 生成、冲突重试、自定义 slug 校验。

## 7. 风险与待验证

| 风险 | 处理方式 |
|---|---|
| Huma 自动校验 422 与 Shlink 400 冲突 | 关闭自动校验，手写校验和 Problem Details |
| Huma 对 `tags[]`、`excludeTags[]` 的解析不兼容 | 先做 spike；必要时用 `Resolver` 从原始 query 解析 |
| Huma 生成的 OpenAPI 与上游不一致 | 只作内部文档，契约测试以上游 Swagger 为准 |
| Bun 关系加载产生额外查询 | 列表页 tags 批量查询，统计用 raw SQL |
| Bun `UpdateModel` 误更新全字段 | PATCH 显式指定列 |
| UA/Bot 识别与 Shlink 的 DeviceDetector 有差异 | 用上游 fixtures 校准；必要时替换解析器 |
| 访问量为 5000/页时查询变慢 | 短链计数列、visits 复合索引、分页查询实测 |
| 同一短链高并发访问导致计数行锁竞争 | 个人场景先接受；后续可改批量写入或异步聚合 |
| 默认域名、自定义域名 Host 处理错误 | 域名规范化和 Host 解析单元测试 |
| 旧 Shlink 数据迁移 | 提供 `migrate-shlink` 和 `SHLINK_SOURCE_DATABASE_URL`，事务式导入到空的新库 |
| 标题自动解析 | 当前不做；如实现必须限制协议、超时、响应大小并防 SSRF |

## 8. 明确不采用

- Gin 之外的 HTTP 框架：Fiber 已评估，最终选择 Gin。
- GORM：隐式行为多，不利于复杂统计和精确 SQL。
- Ent：关系建模和 Atlas 迁移能力强，但 Shlink 关系不复杂，引入成本偏高。
- sqlc：SQL 可控性最好，但动态筛选和 CRUD 开发效率低于 Bun；本项目优先开发效率。
- Redis、RabbitMQ、Mercure、Matomo。
- 微服务、事件总线、独立统计服务。
- 依赖 Huma 默认错误模型和自动校验来满足 Shlink 契约。
- service 层的 repository interface：service 直接持有 `*bun.DB`，只有 `internal/domain` 保留 `Repository` 类型。当前没有替换数据库或按 service 打桩的需求，接口只会增加间接层；需要隔离外部依赖时用窄接口（如 `internal/clock.Clock`）。
